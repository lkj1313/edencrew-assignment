# 국내 주식 관심종목 앱

Flutter 신입 개발자 과제 진행 중인 프로젝트입니다. 관심·검색·종목 상세 화면에 Naver 검색·실시간 시세·종목 기본 정보·일별 시세를 연결했습니다.

## 실행

확인 환경: macOS, Flutter 3.47.4 / Dart 3.13.3, Xcode 26.6.

```bash
flutter pub get
flutter run -d macos
```

Xcode를 설치했지만 명령줄 도구가 다른 경로로 선택되어 있다면 다음과 같이 실행합니다.

```bash
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer flutter run -d macos
```

- macOS 최소 실행 버전은 Flutter SDK에 맞춰 12.0으로 설정했습니다. debug·release에 외부 네트워크 접속 entitlement를 추가했습니다.
- iOS 프로젝트의 최소 버전은 Flutter SDK의 마이그레이션에 따라 15.0으로 설정했습니다.
- Android 인터넷 권한도 추가했으며, Android·iOS 기기 실행은 아직 확인하지 않았습니다.
- Naver API의 CORS 제한 때문에 웹 실행은 지원하지 않습니다.
- 처음 실행하면 관심목록은 비어 있습니다. 검색 탭에서 종목명 또는 6자리 코드를 검색한 뒤 별을 눌러 등록합니다.
- 관심목록은 메모리에 보관하므로 앱을 다시 시작하면 초기화됩니다. 탭을 이동해도 검색어·결과·스크롤 위치는 유지합니다.
- 기본 제공 NotoSansKR 폰트와 `lib/theme` 토큰을 사용합니다. 샘플 가격을 실제 시세처럼 표시하는 대체 동작은 없습니다.

## 구조와 기술 선택

```text
lib/
  main.dart       앱 진입점과 Provider 연결
  models/         종목 식별 정보, 실시간·일별 시세, 기간·정렬 기준
  data/           API·HTML 요청, DTO·모델 변환, 기본 정보·일별 페이지 캐시
  state/          공통 관심목록, 상세 시세·기간별 조회 상태
  screens/        탭 구조, 관심·검색·종목 상세 화면
  widgets/        종목 행, 캔들 차트·요약 카드·일별 표, 탭, 안내, 토스트
  utils/          가격과 등락 표시
  theme/          제공된 디자인 토큰
```

- **Provider + ChangeNotifier**: 여러 화면에서 공유하는 관심목록을 한곳에서 관리합니다. 검색어·로딩 상태처럼 검색 화면에만 필요한 값은 `StatefulWidget`에 둡니다.
- **[http](https://pub.dev/packages/http)**: 클라이언트를 주입할 수 있어 실제 응답을 저장한 파일과 `MockClient`로 네트워크 없이 테스트할 수 있습니다.
- **[charset](https://pub.dev/packages/charset)**: 시세 응답의 `Content-Type`이 EUC-KR인 경우 바이트를 올바르게 해석합니다. 다른 JSON 응답은 UTF-8로 해석합니다.
- **[html](https://pub.dev/packages/html)**: 일별 시세 HTML을 DOM으로 읽어 표의 열과 페이지 링크를 구분합니다. 날짜를 `yyyyMMdd`로 정규화하고, HTML의 상승·하락 표시를 일별 등락 부호로 변환합니다. 장식 행은 제외하고 잘못된 날짜·숫자·OHLC 범위는 오류로 처리합니다.
- **CustomPainter**: 캔들 몸통과 꼬리를 직접 그려 제공된 상승·하락·보합 토큰을 적용했습니다. 차트는 날짜 오름차순, 일별 표는 최신순입니다. 캔들 개수에 맞춰 폭과 간격, 고가·저가에 맞춰 Y축 범위를 자동 조절합니다. 축 라벨·거래량 바·터치 툴팁은 선택 항목으로 구현하지 않았습니다.
- 화면은 `StockRepository`에 정의된 기능을 통해 데이터를 받습니다. 원본 JSON 필드는 DTO에서 해석하고, 화면에는 `Stock` / `StockQuote`를 전달합니다.
- 종목 기본 정보는 등록 시 조회하고 캐시합니다. 같은 코드의 동시 요청도 공유합니다. 검색은 자동완성 응답의 이름·시장으로 빠르게 표시하며, 캐시하거나 관심목록에서 보강한 정보가 있으면 우선 사용합니다. 기본 정보 조회 실패 시 자동완성 API에서 받은 정보를 유지합니다.

## 직접 판단한 동작

- 검색은 입력 후 **300ms** 동안 변경이 없으면 요청합니다. Enter로 즉시 검색할 수 있습니다. 검색어가 바뀌거나 지워지면 이전 응답을 무시하고, 화면이 닫힌 뒤 도착한 응답도 반영하지 않습니다.
- 검색 실패는 결과 없음과 구분하고 재시도 버튼을 표시합니다. HTTP 요청은 10초 후 타임아웃 처리합니다. 국내 주식·6자리 코드만 남기고 중복 코드는 하나로 합칩니다.
- 관심 등록은 즉시 반영합니다. 연속 등록을 **100ms** 동안 모아 관심목록 전체를 한 번의 시세 요청으로 조회합니다. 수동 새로고침도 전체 목록을 묶어 요청합니다.
- 최초 시세 수신 전에는 스켈레톤을 표시합니다. 실패하거나 일부 시세가 없으면 안내와 재시도 버튼을 표시하며, 기존 시세가 있다면 유지합니다. 시세를 한 번도 받지 못한 종목은 `시세 없음`으로 표시합니다. 전일 종가가 0이면 등락을 보합으로 표시하지 않고 `—`로 표시합니다.
- 정렬 기본값은 가나다순입니다. 이름은 대소문자를 구분하지 않는 문자순으로 비교하며, 같은 이름은 종목코드순으로 정합니다. 현재가·등락률은 높은 순서이고, 시세 미수신 또는 등락률 계산 불가 항목은 마지막에 둡니다. 동률이면 이름·코드순으로 정합니다. 새 시세를 받으면 선택 기준대로 다시 정렬하며, 탭 이동 중에는 기준을 유지합니다. 앱 재실행 후 기준 저장은 구현하지 않았습니다.
- 상세 화면은 시세와 일별 데이터를 독립적으로 조회합니다. 한쪽만 실패하면 성공한 영역을 유지하고 실패한 영역만 재시도할 수 있습니다. 기본 정보 조회 실패 시 진입할 때 받은 종목명·시장을 유지하며, 관심 상태는 세 화면이 같은 상태를 구독합니다.
- 기간은 API 가이드의 대략적인 거래일 수인 **20·60·120·245거래일**로 해석했습니다. 최초 1개월은 2페이지, 기간 확대 시 6·12·25페이지까지 부족한 페이지만 순서대로 요청합니다. 받은 페이지와 진행 중인 동일 요청을 공유하며 `lastPage`를 넘지 않습니다. 신규 상장 등 데이터가 적은 종목은 존재하는 구간만 표시합니다.
- 일별 페이지 캐시는 종목별로 **5분** 유지합니다. 만료되면 새 캐시에서 처음부터 읽어 오래된 페이지와 새 페이지를 섞지 않습니다. 기간을 변경하거나 상세 화면을 닫으면 진행 중인 HTTP 응답은 캐시에 보관할 수 있지만, 화면 반영과 후속 페이지 요청은 중단합니다. 실패한 페이지는 캐시하지 않아 재시도 시 성공했던 페이지부터 이어서 사용할 수 있습니다.
- 기간 전환 중에는 해당 기간의 로딩 안내를 표시합니다. 거래 정지 등 OHLC가 0인 행은 표에 남기고 캔들에서는 제외합니다. 보합 캔들과 한 거래일만 있는 경우도 처리하며, 거래량·시가총액의 축약값은 천·억·조 등의 단위 아래를 버립니다.
- 토스트는 **2초** 후 사라지고, 연속 등록·해제 시 마지막 동작의 안내로 교체합니다. 탭 이동 시에는 즉시 닫습니다.
- 긴 종목명은 한 줄 말줄임으로 처리합니다. 결과 없음 문구에는 입력한 검색어를 그대로 넣고, 긴 문구나 작은 화면에서는 안내 영역을 스크롤할 수 있습니다.
- 데스크톱에서는 내용 너비를 393으로 제한했습니다. 실제 기기의 상태 바·하단 안전 영역은 `SafeArea`로 처리하며, Figma의 가상 상태 바를 화면에 직접 그리지 않습니다.
- Figma Properties에서 주요 텍스트 레이어의 크기·행간·자간과 화면 배치를 확인했습니다. `lib/theme`와 폰트 파일은 추가·변경하지 않았습니다. 숫자 일부에 사용된 Figma의 Inter 대신 제공된 NotoSansKR을 유지하므로 숫자 폭에는 차이가 있습니다.
- 간격·반경·아이콘은 기존 토큰을 사용합니다. 목록의 두 줄 사이 2px은 `space1 / 2`로 계산하며, 시안의 요약 카드 내부 9·10px 여백 등은 기존 8px 토큰을 적용했습니다. 정렬창 모서리도 제공된 `radiusLg`를 유지했습니다. 빈 상태 아이콘은 직접 그렸고, 나머지 아이콘은 Flutter Material 아이콘으로 대응해 원본 벡터와 형태 차이가 있습니다.

## 검증

```bash
flutter analyze
flutter test
```

- `flutter analyze`: 문제 없음. `flutter test`: **43개 통과**.
- 기존 검색·관심·정렬 테스트에 HTML 파싱, 페이지 캐시·중복 요청·취소·만료·마지막 페이지 제한, 상세 화면 이동과 관심 동기화, 기간별 차트·표, 오류 재시도, 보합·빈 차트를 추가 검증했습니다. 320px 너비에서 1년 표의 마지막 행까지 스크롤하는 테스트도 포함합니다.
- 실제 Naver 일별 데이터로 1개월 20개, 3개월 60개, 6개월 120개, 1년 245개를 확인했습니다. 누적 요청은 각각 2·6·12·25회였으며, 다시 1개월을 선택하면 추가 요청이 없었습니다.
- macOS 앱에서 실제 검색·관심 목록에서 상세 화면 이동, 1년 245거래일 차트, 상세에서 관심 등록 후 검색 별·관심 목록 동기화를 확인했습니다.
- API 샘플의 취득 시각·인코딩은 [`assets/mock/README.md`](assets/mock/README.md)에 기록했습니다. 샘플은 테스트용이며 실행 중 오류를 숨기는 대체 데이터로 사용하지 않습니다.

## 검수와 구현 중 해결한 점

- Figma의 빈 상태·검색·관심·상세·정렬·토스트를 비교했습니다. 본문 15/20px, 보조 글자 11/14px, 제목 19/22px, 상세 현재가 30/36px 등을 반영하고, 검색창·관심 행·기간 탭·일별 표 열 너비와 정렬창의 왼쪽 체크 표시를 조정했습니다. 색상과 굵기는 기존 토큰에서 가져옵니다.
- 상세의 하락 등락률에서 빠졌던 음수 부호를 수정하고, 화면 테스트에서도 `▼ 9,500 (-3.53%)` 표기를 검사합니다.
- 하단 관심 탭은 시안과 같이 선택했을 때 채워진 별, 선택하지 않았을 때 테두리 별을 표시합니다.
- 393×852 화면과 상단·하단 안전 영역을 넣은 렌더링에서 세 화면과 상태별 배치를 확인했습니다. 키보드가 차지하는 높이를 적용해 토스트가 가려지지 않는지도 검사했습니다.
- 일별 데이터는 JSON이 아니라 EUC-KR HTML이며 등락의 부호가 이미지·텍스트에 따로 들어 있습니다. 실제 응답을 저장해 인코딩과 방향 판독을 검증했고, 기간을 바꿀 때 중복 호출하지 않도록 페이지 단위 캐시와 진행 중인 요청 공유를 사용했습니다.

과제 원문은 [`docs/ASSIGNMENT.md`](docs/ASSIGNMENT.md), API 안내는 [`docs/NAVER_API.md`](docs/NAVER_API.md)에 있습니다.
